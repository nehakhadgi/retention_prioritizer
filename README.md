# Build a Retention Prioritizer

A machine learning project that predicts customer churn and ranks customers by their estimated 12-month value at risk.

The workflow converts churn probabilities into a capacity-aware retention queue. Each selected customer receives a recommended retention action based on their segment.

## What This Project Does

- Loads and cleans IBM's Telco Customer Churn dataset.
- Creates customer segments using tenure, contract, and service usage.
- Trains an explainable logistic regression model.
- Evaluates the model on an untouched holdout cohort.
- Estimates each customer's 12-month value at risk.
- Ranks customers within a fixed campaign capacity.
- Assigns segment-specific retention actions.
- Exports the results to a CSV file.

## Modeling Approach

The project uses a scikit-learn pipeline to standardize numeric features, encode categorical features, and train a logistic regression classifier. Preprocessing is fitted only on the training data to reduce data leakage.

## Model Evaluation

The workflow evaluates the model using accuracy, a confusion matrix, false negatives, average precision, Brier score loss, probability calibration, and model coefficients.

## Retention Prioritization

Each customer receives an annual revenue proxy:

`Annual Revenue Proxy = Monthly Charges × 12`

The workflow estimates value at risk with:

`Value at Risk = Churn Probability × Annual Revenue Proxy`

Customers are ranked from highest to lowest value at risk. The example campaign selects the top 10% of the holdout cohort.

## Retention Actions

- New Explorer: Onboarding check-in.
- Flexible Regular: Contract review.
- Committed Core: Loyalty benefit review.
- Multi-Service Champion: Priority service review.

Customers outside the campaign capacity receive a `Monitor` action.

## Important Limitations

`AnnualRevenueProxy` and `ValueAtRisk12M` are scenario metrics. They are not complete customer lifetime value calculations. A retention team should review the recommendations before using them for customer decisions.
